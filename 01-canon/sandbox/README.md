## 本目录定位

正典有 `01-canon/`（主干叙事 + `assets/` 资产库）；**沙盒此前无实体落点**——核准入沙盒的提案正文只留在 GitHub Issue 历史里，没有沉淀路径。本目录即为该缺环：

- **沙盒 ≠ 正典**：沙盒内容局部自由，但**不得改写正典**；对正典仅为只读引用，冲突以正典为准（卷3 定律一·正典兼容律）。
- **可沉淀**：核准入沙盒的提案正文从 Issue 落盘成独立 md，可独立检索、独立演化（随 `qmd update` 入索引）。
- **不自动升格**：沙盒条目**不自动**转入正典；须经模态坍缩评估后重走正典流程（卷3 定律二·局部沙盒自由律、沙盒轨道定义）。

## 目录结构

```
sandbox/
└── <slug>_vN.md      # 扁平存放，每条一个文件
```

> 首版**扁平存放**，不预分子目录。条目量级上来后，如需按模态（A/B/C）或介入缝类别分类，另议。

## 入库规范

1. 每条 = 一个 md 文件，命名 `slug_vN.md`（N = 递增版本；沿用 `01-canon/assets/` 体例）。
2. 命名 slug 用**英文小写连字符**；条目标题用**中文原文**。
3. 头部含：归属块（`sandbox`）/ 版本 / 编者（提案者 `anon_code`）/ 日期 / 正典锚点（介入缝 · 节点 · 模态）/ 状态 / 来源（GitHub Issue #n · D1 proposal id=n）。
4. 内容须过**三层红线自检**（法则 / 权限 / 元层自洽）；与正典冲突处，一律以正典为准。
5. 库内文件随 `qmd update` 入索引，语义检索可命中。

**条目头部模板**：

```
# <标题>
> 归属块：sandbox · 版本：vN · 编者：<提案者 anon_code> · 日期：YYYY-MM-DD
> 正典锚点：介入缝 <A/B/C 编号> · 节点 <N 编号> · 模态 <A/B/C/跨模态>
> 状态：沙盒（未入正典）
> 来源：GitHub Issue #<n> · D1 proposal id=<n>
```

## 落盘方式

**首版人工落盘**：架构师在 Discord 点「核准入沙盒」后，手动从 GitHub Issue 复制正文落盘到本目录（与「人工回填 `discord_thread_url`」同一策略）。
**后端自动化**（核准入沙盒经 GitHub Contents API 自动 commit）列为 `api-contract_proposal-review.md` §10 待议项，暂不做。
