## 正典定位

紧箍咒 = **维度锁**（授权边界锁 + 破维度形态限制）。是系统的**授权约束工具**（对多态进程），**不是惩罚工具**（卷2 注记反复强调）。作为法宝 = **受限维度权限的具象化**。它在卷1 对照表中归入「权限认证 / 维锁」，与普通法宝并列为权限类具象。

## 定义与机制

- **卷1 定义**：紧箍咒 = 维度锁（给低维进程套上授权边界锁 + 破维度形态限制，多态进程）。
- **卷2 注记**：紧箍咒 = 维度锁（授权边界锁 + 破维度形态限制），是授权范围内的**执行约束，而非惩罚工具**。
- **卷4 法术表**：紧箍咒 = 维度锁 / 秩序常数注入——是对进程的"授权边界锁 + 破维度形态限制"（多态进程），不是普通惩罚。
- **授锁链路（MAINMAP N10）**：Root 级授权给唐僧"维度锁"，约束多态进程执行范围（含破维度形态限制）；观音给悟空戴紧箍，八戒/沙僧各受约束。
- **机制要点**：紧箍咒不是简单的"念咒疼痛"，而是：
  - **授权边界锁**：划定悟空（多态进程）可执行的授权范围，越界即触发约束信号。
  - **破维度形态限制**：专门锁定悟空的破维度形态（逆维度能量触发的异常形态），防止异常资源脱离授权运行——呼应五行山"不删除：异常资源有价值"的逻辑（隔离而非销毁）。
- **与唐僧关系（N10 + 卷3 唐僧权限行）**：唐僧作为**熵减稳定器/纠错触发载体**持有紧箍咒授权，是唯一能约束多态进程执行范围的载体。紧箍咒是唐僧行使"约束纠错进程"职能的机制工具（非情绪化惩罚）。
