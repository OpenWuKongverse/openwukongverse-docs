## 一、为什么需要一套独立的分配逻辑

- **贡献类型不同，价值逻辑不同**：创意产出与生态维护是两类劳动，若共用同一条分配口径，容易互相稀释、激励错配。
- **IP 是长期资产**：优质 IP 的价值来自持续运营与延展，而非一次性交付；分配逻辑应奖励长期深度投入，而非只奖短期产量。
- **分配需要透明可审计**：任何分配都应留有独立、可追溯的账目，避免"暗箱"与信任危机。

> 结论：单一口径难以同时兼顾"创意、生态、长期、透明"，因此需要一套**多维度的分配逻辑**，而非单一池子。

---

## 二、分配逻辑的核心理念

> 让不同性质的贡献，流向不同的分配方向，各自按其逻辑处理；方向之间允许联动（回投/升级），但不互相混装。

区分方向的逻辑维度（取最关键者）：

| 维度 | 区分什么 | 解决什么 |
|---|---|---|
| 按**贡献类型** | 创意产出 / 生态维护 | 创意与运维不互相稀释 |
| 按**贡献深度** | 一次性贡献 / 持续维护 | 奖励长期投入与复利 |
| 按**资产属性** | 短期可变现 / 长期 IP 资产 | 快慢收益不混装 |
| 按**用途** | 直接回报贡献者 / 生态再投入 | 生态有独立造血通道 |

> 以上为原则示意；**具体分成几个方向、各方向如何命名与占比，均待商业化启动时再定**。

## 三、未来分配的通用方向（概念示意）

```
商业化收入（衍生收益 / 授权 / 数字资产等）
        │
        ▼
    收益总池
        │
  ┌─────┼───────────┬───────────┐
  ▼     ▼           ▼           ▼
方向一  方向二        方向三        方向四
(贡献者回报) (生态维护)    (长期资产)    (生态再投入)
```

> **说明**：此图仅为概念示意，不代表最终方向数量或名称。未来具体方向划分、命名与分配比例，将根据实际商业化情况及社区共识动态制定。

### 三、1 各方向的定位（原则层面）

- **贡献者回报方向**：直接回馈内容创作者，按维度积分（C1–C3）体现；引入"资产深度系数"，对持续维护同一 IP 资产的贡献者加权。
- **生态维护方向**：覆盖翻译、社群运营、评审、治理、工具维护等生态劳动，按生态岗独立的运维积分（R1/R2/R3）记录，与维度积分分离。
- **长期资产方向**：投向被认定为长期 IP 资产的原创者与生态建设者，回报与 IP 增值对齐、滚动兑现（暂不启用，待资产化启动）。
- **生态再投入方向**：不直接分给个人，回投于衍生内容、社区活动、工具开发与创作者孵化，服务整体生态增长。

> 各方向的**具体比例与结算规则当前全部留空**，待商业化启动时补定。

## 四、关键机制（原则层面）

### 四、1 维度积分 → 分配方向的映射（原则）

维度积分 C1–C4 分别体现不同性质的贡献，未来按性质归入不同的分配方向，避免"一个积分打天下"。**具体映射表待定。**

> 生态岗的日常协作可另设独立运维积分体系（如服务量 / 满意度 / 生态反馈），与创作者维度积分分离。

### 四、2 资产深度系数（原则已定：奖励长期投入）

- 对同一 IP 资产持续维护的贡献者，分配权重随时间/贡献递增。
- 目的：把"一次性创作者"与"深度运营者"区分开，让最贵的"持续运营"获得回报。
- 落地：作用于分配权重，不改变总量。

### 四、3 分配透明度与监督

- 独立账本，定期公示资金去向。
- 管理方：架构师评审团 + 社区代表。
- 目的：让分配透明化，杜绝"拿走大头不说干嘛"的信任危机。

---

## 五、延展性原则（确保长期兼容）

分配框架应遵循三条原则，保证未来可扩展而不崩：

1. **总量守恒**：任何新增分配方向从既有方向"划拨"，总量恒为 100%。
2. **只增不重构**：新方向启用不改动既有已确认的安排。
3. **独立账本与公示**：每个方向独立记账、独立公示，支持审计。
