## 0. 一句话架构

> 一个共创 Hub（中台） + 三个平台入口。所有创作、投票、积分、公示最终都回流到一个统一的共创 Hub 记账与公开：社媒平台不是"彼此孤立的渠道"，而是 Hub 在不同社交场景下的入口 / 通道 / 展示橱窗。

```
                       ┌─────────────── 共创 Hub（中台 · 单一事实源）───────────────┐
                       │ 正典库(版本化) · 贡献者账户 · 积分账本 · 投票结算 · 公示面板 │
                       └──────────────┬──────────────────────┬───────────────────┘
          拉新/公告 ▸ 创作+评议 ▸      │ 报名/创作/评议/投票   │      结算/公示 ▸
   ┌─────────┐   ┌─────────┐   ┌──────┴─────┐
   │ Bluesky │   │ Reddit  │   │  Discord   │
   │ 广播/曝光│   │ 提案投票 │   │ 社群+讨论   │
   └────┬────┘   └────┬────┘   └──────┬─────┘
        │            │              │
   ┌────▼────────────▼──────────────┴───────────────────────────────┐
   │            信息发布通道（Hub 站 / Bluesky / Reddit）             │
   └──────────────────────────────────────────────────────────────────┘
```

单一事实源原则（对齐卷3）：所有平台都是"前端"，正典判定、积分记账、分润结算的唯一权威在 Hub，任何平台上的点赞/热度都是"输入信号"，不是"结论"。防止"在 Discord 上点赞高就当正典"这类平台割裂。

## 1. 三个平台的定位分工矩阵

> 每个平台按"它最擅长把共创闭环的哪一环做好"来分工，避免平台都干同一件事（内部竞争、数据割裂）。

| 平台 | 性格 / 用户 | 在共创闭环中的角色 | 主要负责 | 与 Hub 的关系 |
|---|---|---|---|---|
| **Discord** | 高密度实时社群、创作人群 | **社群主战场** | 共创评议与讨论、评审会、新手答疑、社群运营（C4 生态） | 最活跃的回流通道：讨论结论沉淀回 Hub |
| **Reddit** | 长文 + 原生投票 + 版主制 | **提案展示 + 投票评议中枢** | 深度提案帖展示、社区投票（原生 upvote 契合评议）、设定解析 | 投票结果回流 Hub 作为评议输入 |
| **Bluesky** | 去中心化协议、短内容、KOL 生态 | **广播 / 公告出口** | 进展公告、节点/难发布、话题讨论、媒体曝光 | 单向广播 + 导流回 Hub/其他平台 |

平台角色速记：
- 想**讨论共创** → Discord（唯一社群/即时讨论通道）
- 想**发提案/投票** → Reddit（提案展示+原生投票）+ Hub 站（提交入口）
- 想**看信息/公告** → Hub 站 + Bluesky（公告广播）+ Reddit（深度提案帖）
- 想**深度参加/报名** → **站内注册表单（CF，主入口，观察者直接入）** + GitHub（熟手）+ Discord（补充/领邀请码）

> 首期聚焦（D6）：Bluesky / Discord / Reddit 三平台先跑。

## 1.5 Hub 站的职能

> Hub 站是整个项目的信息展示与入口主界面：既是后台中台（记账），也是可访问的**前端站点**（信息展示+入口）。**讨论唯一通道为 Discord**（不另建站内论坛/即时讨论区）。

### 1.5.1 Hub 站承担的五项职能

| 职能 | 说明 |
|---|---|
| 报名登记 | 报名集中在 Hub 站内注册表单（CF，主入口；GitHub/Discord 为辅助），开户即建 Hub 账户 |
| 提案提交 | 创作者直接向 Hub 站提交提案（走流水线） |
| 评议投票 | 社区在此投票/评议（评审团加权，卷3 防刷） |
| 积分看板 | 从这里看 C1–C4 积分明细 + 历史（公示透明，全体用户同一入口） |
| 信息公告 | Hub 站发布进展公告、积分看板、D3 四档公示（信息发布通道之一：Hub/Bluesky/Reddit）|

> **讨论唯一通道：Discord。** Hub 站不承载实时讨论，仅提供 Discord 入口导航与信息展示。所有共创者均在 Discord 进行社群讨论、评审、答疑。

### 1.5.2 同一事实源的保证

- 各平台的评议与投票，都作为 C2 质量分 / C3 采用率的输入回流 Hub 统一记账。
- 同一提案可能在不同平台同时评议：**结果合并加权**，不重复计分为两个提案。
- 积分、正典、分润在所有入口下同一套贡献者体系。

## 2. 报名流程（主入口：站内注册表单 CF；辅助：GitHub 熟手 / Discord 补充 / 邮件·路B申请；各平台导流）

> 对齐卷3：参与者从"观察者"起步，靠贡献晋升到"正式共创者 / 评审团"（卷3 4.3）。报名阶段不自设权限门槛，先报名、后凭贡献晋升。

```
[1] 触达（任一平台看到招募）─┬─ Bluesky（公告广播）    │
                             └─ Discord（社群讨论）    │
                              │                      ▼
[2] 报名 ── 站内注册表单（CF，主）直写观察者；GitHub（熟手）/ Discord（补充+领邀请码）辅助
        │  字段：匿名代号 / 主攻角色(画师/编剧/玩家/程序/生态) / 主攻模态(A/B/C) / 联系邮箱
        │  匿名性保护（卷3 + 招募文案承诺：身份隔离，支持匿名代号）
        │  【已定】站内注册表单为主通道（CF Worker→D1，自动建档观察者）；邮箱为 Hub 账户稳定标识（不强制实名，匿名代号仍为公开身份）——**邮箱哈希用于公开/账本留痕（不公开明文）**；明文邮箱另存 Hub 内部发送通道，仅用于发接入套件邮件与通知，不外泄；
        │  创作者路B申请（累积积分转正之外）：站内表单加意向字段，或经邮件/Discord，评审团严格核验
        ▼
[3] 开户 ── 在 Hub 创建「贡献者账户」（匿名代号 + 邮箱绑定 + 主攻角色/模态标签）
        │  初始身份：观察者（C1-C4 从 0 累计）
        ▼
[4] 引导 ── 给新人发「共创接入套件」（邮件 + 对应平台通知）：
        │  介入缝索引(intervention-index) → 提案模板(proposal-template) → 流水线说明(卷3)
        ▼
[5] 首个提案 ── 走流水线：提案 → 评议 → 架构师审查 → 入正典/沙盒（建议从沙盒+A类缝起步）
```

## 3. 提交与评议流程（创作从哪进、评议在哪聚）

| 环节 | 工具/平台 | 说明 |
|---|---|---|
| **挑介入缝** | 介入索引 `01-canon/intervention-index.md` | 按 A/B/C 三类找活干（新手 A 类） |
| **填提案** | 提案模板 `02-co-creation/proposal-template.md` | 一页可填，附三类示范 |
| **提交** | Hub 正典库（GitHub 仓库 PR / Issue）| 唯一正式提交通道，版本化留痕 |
| **展示** | Reddit（提案帖展示 + 原生投票）| 供观察者网络评议 |
| **讨论** | Discord（评议频道）| 深度讨论、质疑、迭代 |
| **投票** | Reddit 投票 + Hub 评审团加权 | 对齐卷3：质量分由社区加权（评审团+观察者投票）非单一点赞 |
| **评审** | 架构师评审团（卷3）| 对照三大沙盒定律 + 合法性自洽终审 |
| **入库** | Hub 正典库 | 入正典标记贡献者 + 当次积分（卷3 4.1）|

> 注意（对齐卷3 防刷）： 各平台上的"点赞"都只算观察者投票输入，须经 Hub 的**防刷/聚类复核**后才计入质量分 C2，防止跨平台刷票（卷3 4.2）。

## 4. 积分累计与公示（对齐卷3 维度积分 C1–C4）

> 卷3 已定：C1 创作量 30% / C2 质量 30% / C3 采用率 20% / C4 生态 20%。本板块只负责怎么累计、怎么公示，不改权重。

### 4.1 来源（每项贡献喂哪个维度）
| 维度 | 事件 | 入口 |
|---|---|---|
| C1 创作量 | 提案提交 / 入正典内容量 | Hub 正典库（GitHub PR/Issue）|
| C2 质量分 | 提案获社区评议加权分 | 评议与投票（Discord + Reddit 双通道并行、评审团加权，卷3 防刷复核）|
| C3 采用率 | 提案被采纳/入正典比例 | Hub 定案记录 |
| C4 生态 | 评审/翻译/社群维护/平台运营 | Discord 社群 / 翻译组 / 评审工作 |

### 4.2 公示面板（积分透明，防"暗箱"）
- **公开积分看板**（Hub 托管，GitHub Pages 或独立页）：按贡献者账户展示 C1–C4 明细 + 综合维度积分 + 历史记录。
- **公示频率（D3 已定稿，2026-08-24）**：**事实源**（积分看板）随每次入库/评审在 Hub 即时更新，永远实时；**对外公告**按事件重要度分四档节奏，各平台照此发布：
  - **重要节点（即时）**：新提案发起、入正典、关键决议 → Bluesky 公告 + Discord 全体频道即时发布
  - **运行周期汇总（每周）**：积分与入库汇总 → Discord 周报 + Bluesky 周更
  - **深度汇总长文（每月）**：机制调整、入库内容说明 → 语雀月刊
  - **重大里程碑（随时）**：整卷完成、公开上线、分润首启 → 全平台特别公告
- **异议通道**：对积分有疑义 → 对账流程（见下）。

### 4.3 对账与异议（对齐卷3 5.4 仲裁）
- 贡献认定争议：架构师评审团 + 社区代表仲裁小组复核。
- 发现平台端点赞被错误计入 → Hub 复核剔除（防刷机制，卷3 4.2）。

## 6. 平台整合的"运行节奏"（一个共创周期怎么转一圈）

> 以"某一个难/节点的共创"为例，看三个平台 + Hub 如何协同转一圈：

```
Round 1 · 发起     Bluesky 公告「下一难：黑风山」→ 各平台同步预告
Round 2 · 聚集     Discord 开评议频道 + Reddit 同步开提案征集帖
Round 3 · 创作     创作者挑缝(索引) → 填提案(模板) → 提交 Hub 正典库
Round 4 · 评议     评议与投票（Discord + Reddit 双通道并行、评审团加权）→ 结果回流 Hub
Round 5 · 评审     架构师评审团对照三定律终审
Round 6 · 入库     Hub 入正典 → 标记贡献者 + 当次积分
Round 7 · 展示     视觉作品展示（Reddit / 站内）→ 再次引流
Round 8 · 公示     Bluesky 公告 + Discord 频道汇总公示（D3 已定稿：重要节点即时 · 运行周报每周 · 长文每月 · 里程碑随时）
Round 9 · 结算(商业化后) 结算与发放通道（细则后议）→ Hub 留痕分配
```

平台不打架的关键： 每轮每条信息都明确"发在哪、回流到哪"。Hub 是唯一事实源，平台负责各自的传播/讨论/展示职能，**不做重复记账**。

## 7. Hub 中台的技术承载（轻量起步，待拍板）

> ⚠️ 以下为**建议选型**，非定稿。是否用去中心化账本（区块链）、还是轻量 GitHub 起步，须架构师/社区拍板。

最轻起步（推荐先跑）：
- 正典库 + 版本化：GitHub 仓库（现已在用）：所有设定/提案以 PR/Issue 管理，天然留痕、可评审、可追溯。
- 贡献者账户 + 积分账本：先以仓库内 Markdown/表格记账（如 `contributors/` + 积分表），人工/半自动维护。
- **公示面板**：GitHub Pages 生成公开积分看板。

**⚠️ 前端可达性（v2.0，D7 已修订）：** 前端站是 Hub 的**统一门面**，同一入口服务全体。GitHub Pages 起步、零成本、全球 CDN 可达；若访问确需优化线路，用**加速层**（OSS/CDN 静态托管）兜底，**不改门面结构、不另建备案站**。GitHub 仓库始终作为正典库/版本化/审议的后台事实源，前端站只读展示。

**统一门面站（D7 v2 修订后）承载：**
- 首页 / 公告（D3 四档公示）
- 世界观速览（卷1/卷2 精华）
- 报名入口（站内注册表单 CF 主入口 / GitHub 熟手 / Discord 补充；Hub 站为唯一报名展示入口，D2 修订已定）
- 提案 / 投票指引（流水线说明 + 指向各平台评议入口）
- 积分看板（只读展示 Hub 事实源积分明细 + 历史）
- （讨论区不在门面站内建——讨论唯一通道为 Discord，无站内论坛/即时讨论区）

### 7.5 路线1 · 免备案工具栈（D7 已定，MVP 先跑）

> 决策（D7 路线1）： 路线1 ： 免备案现成平台先跑起来（腾讯问卷/语雀/腾讯文档），验证热度与流程。零开发、零成本、立刻能跑。路线2 ： Hub 统一门面站（GitHub Pages 静态，同一 URL，不强制备案），在路线1 验证后上线，取代分散工具的门面职能。

| 职能 | 路线1 用（免备案现成工具） | 说明 |
|---|---|---|
| 报名登记 | 腾讯问卷 / 金数据 在线表单 | 免费、可在 Hub 站/Bluesky/Discord 分享链接、后台导出，可设匿名代号字段 |
| 提案提交 | 语雀 / 飞书文档（公开可见）| 可直接编辑、版本留痕，作为提案库 |
| 评议投票 | 腾讯问卷投票 + Discord 问卷链接投票 | 评审团加权人工汇总；卷3 防刷由 Hub 复核 |
| 积分看板 | 腾讯文档在线表格（公开只读）| 或语雀公开页，展示 C1–C4 明细 + 历史 |
| 讨论区 | Discord（唯一即时讨论通道；Hub 站提供入口导航） | 全体共创者统一社群 |
| 公告通知 | Bluesky（广播）+ Hub 站公告页 + Discord 公告频道 | 与路线1 报名/看板衔接 |

路线1 原则： 所有数据仍统一回流 Hub 事实源记账（人工/半自动汇总），不因工具分散而分账；待项目验证后迁移到路线2 正式站。

路线2（统一门面站，v2.0 修订）： GitHub Pages 静态站（或 OSS/CDN 作加速层），一套 URL 服务全体，不依赖 ICP 备案；备案/专属域名仅在确定需要专属加速域名时再议，是加分项不是前提。热度与规模确认后启动。

**后续演进（规模化后，含路线2）：**
- 积分 + 投票 + 防刷自动化：接入开源投票/积分工具或链上合约（如需要，配 Web3 钱包身份关联）。
- 模态坍缩权重自动计算：按卷3 第六板块公式从 C1/C2/C3 实时算 W(A/B/C)。
- 决策： 是否上链（去中心账本）→ 关系到"匿名性 + 不可篡改积分"的两难，优先保匿名性（卷3 + 招募承诺），上链为可选项。
