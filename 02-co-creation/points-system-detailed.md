## 0. 定位与原则

C/E 双轨是 OWKV 贡献积分的**全部量化引擎**，只此两条，不设第三条（不引入 Karma / 声誉值 / 治理币等平行体系）。

- **C 轨（核心贡献 · Contribution）**：不可替代、有门槛、实质性的建设行为，驱动角色晋升、专业加权与未来分润映射。
- **E 轨（参与互动 · Engagement）**：低门槛、可替代、推动社区氛围与传播的行为，换取非核心激励。
- **严格隔离**：两轨的获取途径、用途、审核流程、账本处理完全分离，互不折算、互不污染。
- **单事实源**：所有积分变动必须追溯至 `events_raw`（事件原始记录）与 `ledger`（积分流水账本），并经 `approved_by` 复核后才写入账本。
- **零成本互动不分钱原则**：E 轨积分**永不进入 C1–C4 核心分润账本**，也不能用于晋升正式共创者。

## 1. C 轨（核心贡献）细化

C 轨挂钩核心资产与未来分润，强调"多劳多得、优劳优得、质效并重"。

### 1.1 C1 · 创作量（权重 30%）

目标：鼓励高质量正典内容产出与有效提案。

| 触发事件 | 计分 | 复核方 |
| :--- | :---: | :--- |
| `ACT_PROP_SUB` 提案提交（符合《设定资产库规范》且通过合规初筛） | +10（预备分） | 评审团初筛 |
| `ACT_SAN_APP` 提案进入沙盒试验区（评审团 Approve） | +50 | 架构评审团 |
| `ACT_CAN_MG_S` 正典故事入库（S 级核心） | +600 ~ +1200 | 首席架构师 |
| `ACT_CAN_MG_A` 正典故事入库（A 级次要） | +400 ~ +800 | 首席架构师 |
| `ACT_AST_ADD` 设定资产（人物 / 法宝）入库 | +150 ~ +300 | 架构评审团 |

- **熔断红线**：低于 1500 字、格式不符、或 AI 批量无意义文本灌水 → **直接拒收，不计分**。
- 入库分按内容影响力 / 复杂度分级（S 级核心设定与主线段落给高分，A 级次要设定给中分）。

### 1.2 C2 · 质量分（权重 30%）

目标：鼓励内容精益求精，以同行与社区评审提升质量。

| 触发事件 | 计分 | 复核方 |
| :--- | :---: | :--- |
| `ACT_REV_REP` 提案获「正式共创者 / 架构评审团」有效评议（含修改建议或逻辑分析） | +5 / 条 | 架构评审团 |
| 提案获「观察者」有效勘误 / 建议（经确认有效） | +2 / 条 | 架构评审团 |
| 提案被采纳时，附评议均分 × 0.5 作为 C2 加成 | 均分 × 0.5 | 架构评审团 |

- 恶意灌水 / 无意义评议不计分；有效性由架构评审团判定。

### 1.3 C3 · 采用率（权重 20%）

目标：鼓励内容具备复用性与影响力，被后续创作引用。

| 触发事件 | 计分 | 复核方 |
| :--- | :---: | :--- |
| `ACT_REF_HIT` 正典资产被其他入库正典内容有效引用 | +20 / 次 | 自动化扫描 + 首席架构师抽查 |

- **防刷**：同一作者或强关联 ID 间的引用不计分（同源聚类限额）；引用计数自动扫描，最终有效性由首席架构师随机抽查复核。

### 1.4 C4 · 生态贡献（权重 20%）

目标：鼓励对项目生态有结构性贡献的非创作行为。

| 触发事件 | 计分 | 复核方 |
| :--- | :---: | :--- |
| `ACT_REV_REP` 深度评审报告（含冲突分析 / 修改建议 / 一致性验证） | +10 ~ +50 | 架构评审团 / 首席架构师 |
| `ACT_BUG_FIX` 世界观核心冲突排查（底层物理 / 时间线 / 设定间矛盾，经确认有效） | +30 ~ +200 | 首席架构师 |
| `ACT_TRN_DOC` 官方正典文档翻译（成功合流） | +50 ~ +250 | 架构评审团 |
| 代码工具 / 基础设施贡献（Hub 站、CF Worker、QMD 维护脚本等，合流） | +100 ~ +500 | 首席架构师 |

> ⚠️ **边界（防误读）**：C4 的"社群维护"**特指结构性维护劳动**（组织活动、规则运营、文档整理等），**不含**日常评论 / 转发 / 点赞 / 投票——后者一律归 E 轨。C4 积分与生态岗日常协作的运维积分（R1/R2/R3）分离，二者分别进入未来收益分配的不同方向（具体待商业化启动再定，见 `contribution-pool-design.md`）。

## 2. E 轨（参与互动）细化

E 轨仅用于社区活跃度激励与非核心福利，防止稀释核心创作者权益。

### 2.1 适用对象

**所有观察者**为主要对象；正式共创者亦可同时获取 E 轨积分（双轨并行）。

### 2.2 获取途径与计分

| 行为 | 计分 | 上限 / 备注 |
| :--- | :---: | :--- |
| Discord 官方讨论区活跃发言 | +0.5 ~ +1 / 条 | 每日上限 5 条，防刷屏 |
| 官方公告转帖 / 互动（Bluesky / Reddit 等，需链接举证） | +2 / 条 | 每日上限 2 条 |
| 有效活动参与（主题讨论会 / 投票 / AMA，按规模） | +5 ~ +20 / 次 | 按活动规模核定 |
| 民意投票（非关键性，如三模态倾向调查） | +1 / 次 | — |
| 小型勘误 / 排版建议（经审核） | +1 ~ +5 / 条 | 经审核有效 |

### 2.3 积分用途

- **周边兑换**：社区纪念品、艺术周边、限定头像框等。
- **测试资格门槛**：新内容（游戏 Demo、视觉概念稿）内测优先权。
- **基础权益兑换**：在受控上限内兑换基础社区身份标识或论坛特权。
- **不挂钩核心资产**：E 轨积分**永不直接进入 C1–C4 核心分润账本，不能用于晋升正式共创者**。

### 2.4 防刷与审核

- 所有 E 轨行为设**每日 / 每周获取上限**，防止脚本刷分。
- 由社区管理员（未来可由生态岗 R 级运维者承担）进行人工 / 半自动化审核，排除无效灌水与恶意行为。

## 3. 两轨互动与角色晋升

```
观察者 (Observer) ──首笔有效 C 轨积分──► 正式共创者 (Official Creator)
   ↑ 仅 E 轨积分               ↑ 解锁 C 轨 + E 轨双轨
   （E 轨不能驱动晋升）
```

- **观察者 → 正式共创者**：**唯一途径**是产生第一笔有效 C 轨积分（提案被采纳、发现核心 Bug 等）。**E 轨积分无法驱动晋升**。
- **正式共创者**：双轨并行，既以 C 轨晋升 / 分润，也以 E 轨拿日常激励。
- 角色阶梯与权责见 `roles-and-points-spec.md` §1（观察者 → 正式共创者 → 架构评审团 → 首席架构师）。

---

## 4. 数据契约与账本

- 所有 C/E 轨积分的最终计入，严格遵循 `02-co-creation/contribution-data-spec.md` 定义的事件类型、字段与审核流程。
- **单一事实源**：`events_raw`（唯一写入点）→ `ledger`（积分流水，`approved_by` 防刷）→ 聚合视图 `v_dashboard`（公示喂数）。
- E 轨积分在数据层与 C 轨分列（不同 `dim`），**聚合层不得将 E 轨折入 C1–C4**。
- 数值档位为 **B1 起步基线**，后续可平滑升级 B2（体量 × 质量系数）/ B3（全自动公式），只改计分函数、不改表结构。

## 5. 附则

1. **单轨唯一性**：本细则不引入独立于 C1–C4 与 E-Track 的任何第三条评分体系。
2. **事实源纪律**：表结构与单次计分规则以 `contribution-data-spec.md` 为准；冲突时以数据契约为技术事实源。
3. **版本演进**：本细则自发布起在社区试运行（Beta）；修订须经首席架构师发起并公示 7 日，重大修订走"社区共识 + 评审团 + 架构师"三确认。
4. **与卷3 的关系**：卷3《共创协议》为机制母法；本细则是 C/E 双轨的执行落地契约。
