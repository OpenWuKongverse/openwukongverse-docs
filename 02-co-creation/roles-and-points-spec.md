## 0. 宗旨与设计哲学

本规程定义 OpenWuKongVerse（OWKV）社区参与者的身份进阶模型、权责边界，以及驱动多维宇宙演化的量化评价基准。

核心原则：

1. **单轨驱动，事实源唯一**：全体系以**维度积分（C1–C4）**为唯一贡献度凭证，同时驱动角色晋升、模态坍缩投票与未来分润映射。不另设平行评分体系。所有积分变动必须追溯至结构化事件日志（`events_raw`）与不可篡改的流水账本（`ledger`）。
2. **轻量冷启动与重度沉淀并行**：观察者享有低门槛准入通道；高阶正典创作、评审裁决则设置严格的同行评审与世界观一致性审计。
3. **贡献驱动，杜绝空转**：严禁无实质内容产出的纯投机刷分；普通互动仅限门槛激励，核心分值必须绑定正典资产、有效代码或实质性生态维护。
4. **与世界观权限逻辑同构**：社区角色刻意对齐宇宙内"最高权限也受限"的权限逻辑（卷3 修订1）——首席架构师不能绕过评审团/社区单方改规则。
5. **技术预留，拒绝早熟**：商业化分润与上链通证化**暂行挂起**；本规程只建立精确、防刷、可追溯的单向账本，为未来对接留足确定性数据接口。不在社区冷启动阶段引入先期金融化逻辑。

## 1. 社区角色定位与四层阶梯模型

社区参与者依照贡献深度与审查资质，分为四级进阶身份：

```
[4. 首席架构师 (Chief Architect)] ── 终极事实源维护、系统级设定裁决、正典合流权（Veto）
          ▲
[3. 架构评审团 (Review Panel)] ──── 维度质检员：提案初审、一致性审计、评议加权
          ▲
[2. 正式共创者 (Official Creator)] ─ 宇宙拓荒者：正典拓展、支线提案、设定资产产出
          ▲
[1. 观察者 (Observer)] ──────────── 基础观测者：注册成员、探讨反馈、挑刺纠错、共识投票
```

### 1.1 观察者 (Observer)
- **定位**：初识宇宙的观测源。在观象域边缘参与阅读、勘误、讨论与公开表决。
- **准入条件**：通过 Hub 门面站（`openwkv.xyz/join.html`）完成站内注册（Turnstile 人机验证），或绑定 Discord / GitHub 完成身份关联。
- **权利**：
  1. 浏览全部公开白皮书、正典事件与资产库；
  2. 享有提案初级发起权（提交至待筛选池）；
  3. 享有提案沙盒晋阶的基础投票权（1 人 1 票，基准权重）；
  4. 在 Discord 讨论区发起评议并提交勘误报告。
- **义务与红线**：
  - 不得使用多重虚拟账号（Sybil）刷票；严禁发布违背底层物理法则（五层膜 / 五重法则）的破坏性灌水。

### 1.2 正式共创者 (Official Creator)
- **定位**：多维宇宙的实质构筑者。负责主线节点填充、介入缝拓展、设定资产及多模态视觉工程。
- **准入条件**（满足其一即可申请，经架构评审团审核、首席架构师备案）：
  1. 提交 ≥1 个提案并被采纳（入正典或沙盒）→ 自动获正式共创者资格；
  2. 或累计维度积分达到门槛（`C1 + C2 ≥ 阈值`，具体数值待定，对齐 `03-community` E1）；
  3. 或经 2 名正式共创者 / 架构评审团成员推荐 + 首席架构师确认（特殊才能通道，如画师 / 翻译）。
- **权利**：
  1. 享有免初筛的提案提交特权，自动建立独立沙盒分支；
  2. 拥有在入库正典中保留永久作者署名（创作者代号）的权利；
  3. 享有针对其他创作者沙盒提案的专业评议加权；
  4. 解锁 Discord 共创者研讨工坊席位。
- **义务与红线**：
  - 严格遵守《世界观圣经》（卷2）与《设定资产库规范》；杜绝 AI 批量空洞文本；**禁止写死菩提祖师、真假美猴王、取经终局三大留白钩子**。

### 1.3 架构评审团 (Review Panel)
- **定位**：宇宙低熵稳定系统的守护者与单元测试执行官。负责把控设定严谨性与冲突核验。
- **准入条件**（须同时满足）：
  1. 在正式共创者身份上持续活跃（如 ≥3 个月 + 稳定贡献记录）；
  2. 累计维度积分达到较高门槛（C1–C4 综合，具体数值待定，对齐 `03-community` E1/E2）；
  3. 展示正典理解与仲裁能力（参与过 ≥N 次评审 / 争议讨论）；
  4. 经**社区推选 / 共识**产生（非自荐）；规模建议 5–9 人（奇数），任期建议 1 年、可连任。
- **权利**：
  1. 拥有对沙盒提案的合流 / 驳回推荐权（评审 Approve / Request Changes）；
  2. 在全社区提案评议中享有专业加权投票权（C2 质量赋分）；
  3. 享有审查津贴（C4 生态分）与季度治理荣誉标识。
- **义务与红线**：
  - 必须给出详实的逻辑审查报告，严禁无理由否决；评审存在利益关联的提案时必须回避。

### 1.4 首席架构师 (Chief Architect / Echo-Architect-0)
- **定位**：核心系统维护者与终极裁决方；项目发起人固定担任。
- **职责与权限**：
  1. 维护卷1 / 卷2 正典；终审"入正典"、正典仓库最终合并合流权（Git Merge）；
  2. 针对颠覆底层物理逻辑的提案拥有一票否决权（Veto）；
  3. 负责全局参数（如模态坍缩权重 `W(A/B/C)`）的宏观调控与版本更迭。
- **权限边界**（对齐卷3 修订1 权限受限原理）：**不能绕过架构评审团 / 社区共识单方修订规则**；重大规则修订须走"社区共识 + 评审团 + 架构师"三确认。
- **传承机制**（预留，长期项）：可指定继承人（须经评审团 + 社区共识确认），或转为"评审团集体决策 + 首席架构师席位轮值"。

### 1.5 角色权责对照矩阵

| 权限维度 | 观察者 | 正式共创者 | 架构评审团 | 首席架构师 |
| :--- | :---: | :---: | :---: | :---: |
| **基础提案发起权** | ✅（需合规初筛） | ✅（优先通道） | ✅ | ✅ |
| **沙盒支线开辟权** | ❌ | ✅ | ✅ | ✅ |
| **正典资产署名权** | ❌ | ✅ | ✅ | ✅ |
| **大众投票表决权** | ✅（基准 1 票） | ✅（基准 1 票） | ✅（专业加权） | ✅ |
| **提案同行评审权** | ❌ | ❌ | ✅（签署 Review 意见） | ✅ |
| **PR 审查与合并标记** | ❌ | ❌ | ✅（Approve 标记） | ✅（最终 Merge 权） |
| **系统级设定一票否决** | ❌ | ❌ | ❌ | ✅ |

> **生态岗**（翻译 / 社群 / 评审 / 治理 / 工具维护）为正式共创者的子类，按独立的运维积分体系（R1/R2/R3）计分、参与未来收益分配（详见 §3.4 与 `contribution-pool-design.md`）。生态岗日常协作走独立运维积分，与维度积分 C1–C4 分离。

## 2. 贡献力度量：维度积分 C1–C4（唯一驱动）

### 2.1 四维构成与权重

全体系以维度积分（Contribution Score）为唯一贡献度凭证，各维度归一化（0–100）后加权求和。

`Total Points = C1 + C2 + C3 + C4`（基线权重：C1 30% / C2 30% / C3 20% / C4 20%）

- **C1 创作量（权重 30%）**：入正典内容量 / 有效提案数。
- **C2 质量分（权重 30%）**：社区评议加权（架构评审团 + 观察者投票）。
- **C3 采用率（权重 20%）**：提案被采纳 / 入正典的比例。
- **C4 生态贡献（权重 20%）**：评审、架构、翻译、社群维护等非创作贡献。

> **积分用途**（对齐卷3 4.3）：① 分润分配基数（见 `contribution-pool-design.md`）；② 共创角色晋升（观察者 → 正式共创者 → 架构评审团）；③ 模态坍缩投票加权（见卷3 第六板块）。

### 2.2 单项计分口径（数据契约，B1 简单计数起步）

> 计分规则以 `02-co-creation/contribution-data-spec.md`（`OWKV-DATA-SPEC-v1`，已批）为**唯一事实源**；下表为本规程视角的速览，冲突时以数据契约为准。

| 维度 | 触发事件 | 单次计分（B1 建议） | 复核方 |
| :--- | :--- | :---: | :--- |
| **C1 创作量** | 提案提交 / 入正典 | 有效提案 = 1 分；入正典 = 再 +3 分 | 架构师审查 |
| **C2 质量分** | 每获一条有效评议 | 有效评议 = 1 分；提案获采纳时附评议均分 ×0.5 | 评审团加权 |
| **C3 采用率** | 提案被采纳 | 采纳 1 案 = 按案计分（比率维度，归一化在聚合视图） | 架构师审查 |
| **C4 生态贡献** | 评审 1 案 / 翻译 1 篇 / 运维按周 | 评审 1 案 = 1 分；翻译 1 篇 = 2 分；运维按周 = 基准分 | 评审团 |

> 所有单次计分**须经 `approved_by` 复核后才写入账本**（对齐卷3 防刷聚类），未复核不计分。数值档位为 **B1 起步基线**，后续可平滑升级 B2（体量 × 质量系数）/ B3（全自动公式），只改计分函数不改表结构。

### 2.3 参与互动（E-Track / 辅助轨道）

为激励观察者活跃度，设置独立的 **E-Track（Engagement）参与积分**（对齐 `contribution-data-spec.md` 的 E 轨道）：

- **获取途径**：Discord 活跃发言、官方动态转帖互动、有效活动参与（`+0.5 ~ +5` 分 / 次，周级去重）。
- **硬性红线**：E-Track 积分**不直接进入核心 C1–C4 分润账本**，仅用于社区内部周边兑换、测试资格门槛，或按受控上限兑换基础权益，防止刷赞行为稀释核心创作者权益。

## 3. 声誉与权重：由维度积分驱动（不再另设平行体系）

### 3.1 权限与晋升的唯一度量衡

角色晋升与高级权限**全部以累计维度积分（C1–C4）为准**，不引入独立的"声誉值"体系：
- 观察者 → 正式共创者：`C1 + C2 ≥ 阈值` 或提案被采纳（见 §1.2）。
- 正式共创者 → 架构评审团：C1–C4 综合较高门槛 + 持续活跃 + 社区推选（见 §1.3）。
- 治理权重与高级权限严格依赖维度积分门槛，抬高恶意刷小号的攻击成本（防女巫屏障）。

### 3.2 投票机制（对齐卷3：驱动模态坍缩权重）

- **大众与共创者**：1 人 1 票（基准权重）。
- **架构评审团**：在提案评议中享有**专业加权**（其 C2 质量赋分权重更高，对齐卷3"质量分由社区加权而非单一点赞"）。
- **权重归流**：所有投票、创作量与采用率（对应维度积分 C1 / C2 / C3）**周期汇流，驱动模态坍缩权重 `W(A/B/C)`**（三模态各初始 1/3；单一模态不得被完全边缘化，多样性底线 15%）——这是全库唯一的 `W` 符号语义，详见卷3 第六板块与 `01-canon/mode-collapse-table.md`。

> 本规程**不定义个人投票权重公式**；投票的最终效果通过模态坍缩权重 `W(A/B/C)` 体现，由维度积分的持续输入动态调权。

### 3.3 升级路径

积分与角色的晋升路径（对齐 `03-community/community-structure.md`）：
```
观察者 ──(提案被采纳 或 C1+C2 达标)──► 正式共创者 ──(持续贡献 + 社区推选)──► 架构评审团
```
首席架构师由发起人固定担任；退出 / 降级 / 除名 / 任期机制见 `03-community/community-structure.md` 第 3 节。

### 3.4 C4 生态贡献与生态岗的分工（对齐收益分配原则）

- **C4 生态贡献积分** → 属创作者维度的生态贡献，与 R 级运维积分分离，二者分别进入未来收益分配的不同方向（具体方向与比例待商业化启动再定）。
- **生态岗日常协作**（翻译 / 社群运营 / 评审 / 治理 / 工具维护）→ 按**独立的运维积分体系（R1 服务量 / R2 满意度 / R3 生态反馈）**记录，参与未来收益分配。
- 二者分离：C4 是"创作者的生态贡献维度积分"，R 级是"生态岗劳动运维积分"，不混算（详见 `contribution-pool-design.md`）。

## 4. 提案评审流转与积分发放流水线

所有涉及 C1–C4 记账的动作必须通过四阶段闭环流水线，严禁任何形式的人工暗箱加分（对齐卷3 第二板块）：

```
+---------------+   合规初筛   +---------------+   同行评审   +---------------+   合流Merge   +---------------+
| 阶段一: 提出  | -----------> | 阶段二: 沙盒  | -----------> | 阶段三: 正典  | -----------> | 阶段四: 结清  |
| (Draft/Issue) |  通过(+10Pts) | (Sandbox PR)  |  通过(+50Pts) | (Canon Asset) | (+200~500Pts) | (账本写入入库)|
+---------------+               +---------------+               +---------------+               +---------------+
```

1. **阶段一 · 登记与合规初筛**：按模版提交提案；审查维度 = 是否触碰术语红线 / 是否违背底层物理逻辑 / 是否符合格式规范；通过者发放初筛积分并在沙盒区开辟分支。
2. **阶段二 · 沙盒沉淀与同行评议**：进入公开评审期（7~14 天），评审团及全社区展开讨论、出具修改建议；评审团履行单元测试职能，检查交叉碰撞；评审员在此阶段获取 C2 / C4 积分。
3. **阶段三 · 首席架构师审查与正典合流**：架构师最终一票核准，合并进入 `01-canon/` 对应资产目录；触发正典终审积分计算，向作者结算大额 C1 积分。
4. **阶段四 · 不可篡改记账**：触发 D1 事务，在账本中追加不可逆记录，并刷新贡献者账户聚合数值（对齐 `contribution-data-spec.md` 表结构）。

## 5. 防刷、反女巫（Anti-Sybil）与风控红线

为确保积分在未来对接真实权益时不被稀释，设立以下系统级防线：

1. **零成本互动不分钱原则**：站内点赞、表情回应、转发扩散仅用于活跃度统计或有限的门槛兑换，**绝不允许直接折算为核心 C1–C3 积分**。
2. **聚类审查与关联交易回避**：严禁团队或个人建立多个马甲互相引用资产以套取 C3 衍生分；同一作者或强关联 ID 间的引用不计入被引用分成。
3. **同源聚类限额**：单用户每日提交提案上限为 2 篇，超出部分自动进入排队队列，不计即时积分。
4. **格式与字数熔断**：正典类投稿低于 1500 字或不符合《设定资产库规范》者，系统直接拒收，不计入 C1。
5. **硬核降维惩罚**：发现抄袭、恶意大模型无意义文本倾倒、黑客攻击注入者，由架构师执行**封禁（Ban）**：
   - 冻结对应代号下的所有未兑现积分；
   - 其作品从沙盒及正典中强制除名，回滚至最近稳定快照；
   - 严重者直接封禁 Member ID；争议交仲裁小组（架构评审团 + 社区代表）复核。

| 扩展列 | 类型 | 说明 |
| :--- | :--- | :--- |
| `role` | TEXT DEFAULT 'observer' | `observer` / `creator` / `reviewer` / `architect`（§1 阶梯） |

> `contributors.status`（数据契约既有列）继续承载 `observer → contributor → reviewer` 的晋升状态；`role` 表达当前权限身份，二者保持同步。**不设声誉值列、不设钱包 / 链上地址列**——本规程以维度积分 C1–C4 为唯一驱动；商业化与上链暂行挂起（§0.5），启动时按《数据规范》"演进预留"再行扩展。
