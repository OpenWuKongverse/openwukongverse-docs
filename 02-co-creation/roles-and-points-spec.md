## 0. 宗旨与设计哲学

本规程定义 OpenWuKongVerse（OWKV）社区参与者的身份进阶模型、权责边界，以及驱动多维宇宙演化的量化评价基准。

核心原则：
1. **双轨解耦**：区分**不可转移的永久声誉（Karma）**与**可结算的贡献积分（Points）**。声誉代表生态地位与治理权限权重，只增不减；贡献积分代表工作量证明与未来权益映射。
2. **轻量冷启动与重度沉淀并行**：观察者享有低门槛准入通道；高阶正典创作、评审裁决则设置严格的同行评审与世界观一致性审计。
3. **技术预留，拒绝早熟**：商业化分润与上链通证化暂行挂起，本规程只建立精确、防刷、可追溯的单向账本，为未来对接留足确定性数据接口。

## 1. 社区角色定位与四层阶梯模型

社区参与者依照贡献深度与审查资质，分为四级进阶身份：

```
[4. 架构师 (Architect)] ────── 终极事实源维护、系统级设定裁决、正典合流权
          ▲
[3. 评审团 (Reviewers)]  ────── 维度质检员：提案初审、一致性审计、评议加权
          ▲
[2. 共创者 (Creators)]   ────── 宇宙拓荒者：正典拓展、支线提案、设定资产产出
          ▲
[1. 观察者 (Observers)]  ────── 基础观测者：注册成员、探讨反馈、挑刺纠错、共识投票
```

### 1.1 观察者 (Observer)
- **定位**：初识宇宙的观测源。在观象域边缘参与阅读、勘误、讨论与公开表决。
- **准入条件**：通过 Hub 门面站（`openwkv.xyz/join`）完成站内注册，或绑定 Discord / GitHub 完成身份关联。
- **权利**：
  1. 浏览全部公开白皮书、正典事件与资产库；
  2. 享有提案初级发起权（提交至待筛选池）；
  3. 享有提案沙盒晋阶的基础投票权（1 人 1 票）；
  4. 在 Discord 讨论区发起评议并提交勘误报告。
- **义务与红线**：
  - 不得使用多重虚拟账号（Sybil）刷票；严禁发布违背底层物理法则（五层膜/五重法则）的破坏性灌水。

### 1.2 共创者 (Creator)
- **定位**：多维宇宙的实质构筑者。负责主线节点填充、介入缝拓展、设定资产及多模态视觉工程。
- **准入条件**：
  - 累计声誉值达到晋升门槛（$\text{Karma} \ge 100$）；或
  - 至少有 1 个提案通过评审团合规初筛并进入沙盒阶段。
- **权利**：
  1. 享有免初筛的提案提交特权，自动建立独立沙盒分支；
  2. 拥有在入库正典中保留永久作者署名（创作者代号）的权利；
  3. 享有针对其他创作者沙盒提案的专业评议加权；
  4. 解锁 Discord 共创者私密研讨工坊席位。
- **义务与红线**：
  - 严格遵守《世界观圣经》（卷2）与《设定资产库规范》；杜绝 AI 批量空洞文本；禁止写死菩提祖师、真假美猴王、取经终局三大留白钩子。

### 1.3 评审团 (Reviewer)
- **定位**：宇宙低熵稳定系统的守护者与单元测试执行官。负责把控设定严谨性与冲突核验。
- **准入条件**：
  - 累计声誉值达到 $\text{Karma} \ge 1000$；且
  - 至少有 2 项重要资产合并入正典，或提交过重大维度冲突修复报告；经架构师或现任评审团 2/3 联名推荐。
- **权利**：
  1. 拥有对沙盒提案的合流/驳回推荐权（评审 Approve / Request Changes）；
  2. 在全社区提案评议中享有声誉二次方加权投票权；
  3. 享有审查津贴（C4 生态分）与季度治理荣誉标识。
- **义务与红线**：
  - 必须给出详实的逻辑审查报告，严禁无理由否决；评审存在利益关联的提案时必须回避。

### 1.4 架构师 (Architect / Echo-Architect-0)
- **定位**：核心系统维护者与终极裁决方。
- **职责与权限**：
  1. 正典仓库代码及文档的最终合并合流权（Git Merge）；
  2. 针对颠覆底层物理逻辑的提案拥有一票否决权（Veto）；
  3. 负责全局参数（如模态坍缩权重 $W(A/B/C)$）的宏观调控与版本更迭。

## 2. 声誉体系（Karma / 维度声誉值）

### 2.1 概念与特性
- **不可转移性**：声誉值直接绑定参与者代号与核心凭证哈希，不可转移、不可借贷、不可买卖。
- **只增不减（抗通缩/抗惩罚性穿透）**：正常贡献行为赋予正向 Karma。恶意违规直接封禁身份，不采用“扣除部分 Karma”的模糊手段。
- **计算原则**：Karma 基于经过验证的历史贡献沉淀，是角色晋升与投票加权的唯一度量衡。

### 2.2 Karma 获取基准
$$\Delta\text{Karma} = \sum (\text{有效动作基准值} \times \text{质量系数})$$

| 触发行为 | 动作分类 | $\Delta\text{Karma}$ 增量 | 判定依据与审核方 |
|---|---|---|---|
| **站内注册并完成凭据关联** | 基础激活 | $+10$ | CF Worker 自动校验（防机器人） |
| **有效勘误 / 错别字 / 格式排版修复** | 维护修正 | $+5$ | GitHub PR 合并确认 |
| **发现重大设定/维度拓扑逻辑漏洞** | 架构漏洞检出 | $+30 \sim +50$ | 架构师签发确认 |
| **独立沙盒提案获准建立** | 内容开辟 | $+20$ | 评审团初审通过 |
| **沙盒提案转为官方入库资产** | 正典落盘 | $+100 \sim +300$ | 依资产重要度由架构师最终 Merge |
| **完成 1 份符合标准的详实评审报告** | 同行审计 | $+15$ | 提案人与架构师双向确认有效 |

### 2.3 治理权重放大：二次方治理（Quadratic Voting）
在涉及宇宙关键主线发展或模态演化的大型提案表决中，参与者的投票权重 $W$ 不采用简单的一人一票或代币垄断，而是与声誉值挂钩：
$$W = \lfloor\sqrt{\text{Karma}}\rfloor$$
*注：普通观察者（Karma=16）拥有 4 票权重；资深共创者（Karma=400）拥有 20 票权重；资深评审官（Karma=1600）拥有 40 票权重。既保证资深成员的专业权重，又遏制寡头独裁。*

## 3. 贡献积分（Points / C1–C4）量化模型

贡献积分（Cred）记录参与者在特定周期内的实际有效产出。当前严格沿用卷3及《数据规范》确立的四维度框架。

### 3.1 四维积分构成
$$\text{Total Points} = C_1 + C_2 + C_3 + C_4$$

- **$C_1$ 创作基建分（基准权重 30%）**：面向故事正文、主线节点、分镜脚本、原画资产的实质内容生产。
- **$C_2$ 质量评审分（基准权重 30%）**：同行评议、深度修改建议及高水准作品附加评审加权分。
- **$C_3$ 衍生采用分（基准权重 20%）**：节点被其他创作者引申、交叉引用及二创衍生的被引用收益。
- **$C_4$ 生态共建分（基准权重 20%）**：代码开发、工具建设（如 CF Worker/D1/QMD）、翻译多语言、社区日常运维。

### 3.2 单项量化计分细则（初版推荐值）

```
[事件产生: GitHub PR / 站内表单 / 评审表]
               │
               ▼
   [写入 events_raw (临时待核)]
               │
      [经 Reviewer / Architect 复核]
               │
               ▼
[写入 point_logs (不可篡改账本) & 累加用户积分]
```

| 积分维度 | 触发事件 / 产出项 | 基础分值 | 上浮/调节规则 |
|---|---|---|---|
| **$C_1$ 创作** | 提交合规提案并入沙盒 | $+30$ | 格式严格符合 `PROPOSAL-TPL` |
| **$C_1$ 创作** | 完整人物/法宝/术法资产合并入正典 | $+150 \sim +300$ | 依字数、设定复杂度与独立性评定 |
| **$C_1$ 创作** | 主线剧情关键节点（大事件）合并 | $+500$ | 核心主线事件地图落盘 |
| **$C_1$ 创作** | 正典级多模态美术/分镜设定稿 | $+200 \sim +600$ | 原创度、视觉完成度与模态匹配度 |
| **$C_2$ 质量** | 评审团出具标准评审意见单 | $+10$ / 案 | 须指出世界观兼容性与漏洞 |
| **$C_2$ 质量** | 正典提案获评社区“杰出作品” | 原 $C_1 \times 30\%$ | 周期内社区高票评选的前 10% 作品 |
| **$C_3$ 衍生** | 自身设定资产被后续新正典引用 | $+20$ / 次 | 资产间建立显式拓扑链接 |
| **$C_3$ 衍生** | 支线沙盒被其他共创者扩写形成连环故事 | $+50$ / 衍生篇目 | 由衍生作者主动标注引用源 |
| **$C_4$ 生态** | 完成 1 篇完整文档的多语言本地化翻译 | $+50 \sim +100$ | 经母语校对通过 |
| **$C_4$ 生态** | 核心工具开发与基础设施维护 PR 合并 | $+50 \sim +200$ | 涉及站点、索引、API 与数据库服务 |
| **$C_4$ 生态** | 观察者提交有效排版/错漏修正 PR | $+5$ / 处 | 聚合批量提交，防止微小无意义刷 PR |

## 4. 提案评审流转与积分发放流水线

所有涉及 $C_1 \sim C_4$ 记账的动作必须通过三阶段闭环流水线：

```
+---------------+     合规初筛     +---------------+     同行评审     +---------------+     合流Merge     +---------------+
| 阶段一: 提出  | ---------------> | 阶段二: 沙盒  | ---------------> | 阶段三: 正典  | ---------------> | 阶段四: 结清  |
| (Draft/Issue) |   通过(+10 Pts)  | (Sandbox PR)  |   通过(+50 Pts)  | (Canon Asset) |  (+200~500 Pts) | (账本写入入库)|
+---------------+                  +---------------+                  +---------------+                  +---------------+
```

1. **阶段一：登记与合规初筛**
   - 观察者/共创者按照模版提交提案。
   - 审查维度：是否触碰术语红线、是否违背底层物理逻辑、是否符合格式规范。
   - 结果：通过者发放初筛积分，在沙盒区开辟对应分支。
2. **阶段二：沙盒沉淀与同行评议**
   - 进入公开评审期（7~14 天），评审团及全社区展开讨论，出具修改建议。
   - 评审团履行单元测试职能，检查交叉碰撞。评审员在此阶段获取 $C_2 / C_4$ 积分。
3. **阶段三：架构师审查与正典合流**
   - 架构师进行最终一票核准，合并进入 `01-canon/` 对应资产目录。
   - 触发正典终审积分计算，向作者结算大额 $C_1$ 积分及 Karma 声誉增量。
4. **阶段四：不可篡改记账**
   - 触发 Cloudflare D1 事务，在 `point_logs` 中追加不可逆记录，并刷新 `users` 表当前可用积分。

## 5. 防刷、反女巫（Anti-Sybil）与风控红线

为确保积分在未来对接真实权益时不被稀释，设立以下系统级防线：

1. **零成本互动不分钱原则**：
   - 站内点赞、表情回应、转发扩散仅用于活跃度统计或有限的门槛兑换，**绝不允许直接折算为核心 $C_1 \sim C_3$ 积分**。
2. **聚类审查与关联交易回避**：
   - 严禁团队或个人建立多个马甲互相引用资产以套取 $C_3$ 衍生分。同一作者或强关联 ID 间的引用不计入被引用分成。
3. **硬核降维惩罚**：
   - 发现抄袭、恶意大模型无意义文本倾倒、黑客攻击注入者，由架构师执行**封禁（Ban）**：
     - 冻结对应代号下的所有未兑现积分；
     - 其作品从沙盒及正典中强制除名，回滚至最近稳定快照。

## 6. 技术实现与数据契约映射（Cloudflare D1）

本规程定义的数据实体直接映射为 Cloudflare D1 边缘数据库 Schema：

### 6.1 用户核心态表（`users`）
```sql
CREATE TABLE IF NOT EXISTS users (
    id TEXT PRIMARY KEY,               -- 用户唯一UUID
    handle TEXT UNIQUE NOT NULL,       -- 社区匿名代号 (如 Echo-A12)
    email_hash TEXT,                   -- 邮箱加盐SHA256 (不留存明文)
    github_id TEXT,                    -- GitHub 绑定的标识
    discord_id TEXT,                   -- Discord 绑定的标识
    role TEXT DEFAULT 'observer',       -- observer | creator | reviewer | architect
    karma INTEGER DEFAULT 0,           -- 永久维度声誉值 (只增)
    points_c1 INTEGER DEFAULT 0,       -- 创作基建积分
    points_c2 INTEGER DEFAULT 0,       -- 质量评审积分
    points_c3 INTEGER DEFAULT 0,       -- 衍生采用积分
    points_c4 INTEGER DEFAULT 0,       -- 生态共建积分
    total_points INTEGER DEFAULT 0,    -- 当前总可用积分 (C1+C2+C3+C4)
    status TEXT DEFAULT 'active',      -- active | suspended | banned
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.2 不可篡改积分日志表（`point_logs`）
```sql
CREATE TABLE IF NOT EXISTS point_logs (
    id TEXT PRIMARY KEY,               -- 流水号UUID
    user_id TEXT NOT NULL,             -- 关联用户UUID
    dimension TEXT NOT NULL,           -- C1 | C2 | C3 | C4 | KARMA
    delta INTEGER NOT NULL,            -- 积分变动数值 (+/-)
    action_code TEXT NOT NULL,         -- 操作类型代码 (如 CANON_ASSET_MERGED)
    ref_type TEXT,                     -- 引用实体类型 (github_pr | proposal_id | review_id)
    ref_id TEXT,                       -- 引用实体唯一标识
    operator_handle TEXT NOT NULL,     -- 核准人代号 (Reviewer/Architect)
    remark TEXT,                       -- 简要说明
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```
