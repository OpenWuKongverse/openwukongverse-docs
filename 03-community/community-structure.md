# OpenWuKongVerse 文档集 · 《社区基础架构》v1
## 四角色体系 · 进入/退出机制 · 三阶段演进

> 文档代号：`OWKV-COMM-STRUCT-v1`
> 层级：机制/运营层（承接卷3 共创协议与草案治理条款的落地组织设计）
> 性质：定义社区的**四类角色**（首席架构师 / 架构评审团 / 共创者 / 观察者）及其**进入与退出机制**，并给出**分阶段演进**路径（冷启动 → 公开扩张 → 成熟治理）。
> 版本：v1.0（设计稿）
> 编者：Echo-Architect-0
> 日期：2026-08-23
> 关联：卷3《共创协议》（角色权限矩阵 / 晋升逻辑）/ 《共创协议草案》（治理结构·第九章）/ `creator-management-system_v1.md`（运营体系）/ 多池分润（回流基金管理方=评审团+社区代表）
> 对齐原则：不另起炉灶，把既有条款落成"可执行的组织结构"；与草案治理结构（评审团+社区代表+架构师+匿名性）严格一致。

## 0. 设计原则（三条）

1. **与世界观权限逻辑同构**：社区角色设计刻意对齐宇宙内权限逻辑（卷3 修订1）——"最高权限也受限"：首席架构师不能绕过评审团/社区单方面改规则，评审团不能绕过共创者共识，共创者不能绕过正典兼容。
2. **进入门槛递增、退出路径清晰**：越往上越难进（需要贡献/推选/共识），但任何角色都有明确的退出/降级通道，防止"上得去下不来"的僵化。
3. **分阶段放权**：冷启动期小圈子集中决策（速度快），随社区规模增长逐步放权给评审团与社区（治理成熟），最后演进到去中心化（上链/可审计）。

## 1. 四角色总览

| 角色 | 定位 | 核心权限 | 核心责任 | 对应卷3/草案 |
|---|---|---|---|---|
| **首席架构师**（发起人 Echo-Architect-0） | 元层/物理层正典守护者 | 维护卷1/卷2 正典；终审"入正典"；重大争议最终裁定 | 宇宙一致性；最终把关 | 草案第二章·发起人/架构师 |
| **架构评审团** | 正典兼容审查与仲裁 | 审查提案是否违背正典兼容律；仲裁贡献/分润争议；共管生态回流基金 | 正典质量；争议仲裁 | 草案·评审团 + 多池·基金管理方 |
| **共创者**（含生态岗） | 内容生产主力 | 提交提案、创作、评议投票、享分润权 | 产出高质量内容；维护正典 | 草案·正式共创者 |
| **观察者 / 读者** | 受众与输入源 | 投票、点赞、影响模态坍缩权重 | 提供观测输入；可晋升 | 卷3·观测者 + 卷1 桥四 |

> **生态岗**（翻译/社群/评审/治理/工具维护）为共创者的子类，按运维积分（C4）独立计分、参与生态运维池分润（多池分润②）。

## 2. 各角色的进入机制

### 2.1 观察者（最低门槛，开放）
- **进入**：开放注册，零门槛。报名主入口 = **站内注册表单（CF Worker→私有 DB，直接建档观察者）**；GitHub（熟手）/ Discord（补充·领邀请码）辅助；微信/小红书仅人工引导展位（不入数据流）——报名统一回流 creator-sys 报名流程。创作者两层：路A 累积积分自动转正 / 路B 直接申请（评审团严格核验）。
- **初始身份**：匿名代号 + 邮箱绑定（D2 已定），不强制实名。
- **权限**：投票、点赞、浏览、参与评议讨论；影响模态坍缩权重（W）。

### 2.2 共创者（观察者晋升，贡献门槛）
- **进入条件**（满足其一即可申请）：
  1. 提交 ≥1 个提案并被采纳（入正典或沙盒）→ 自动获共创者资格；
  2. 或累计维度积分达到门槛（如 C1+C2 ≥ 阈值，具体数值待定）；
  3. 或经 2 名共创者/评审团成员推荐 + 架构师确认（特殊才能通道，如画师/翻译）。
- **申请方式**：向 Hub 提交"共创者申请"（含匿名代号、主攻角色/模态、贡献记录）。
- **审批**：架构评审团审核（对照三大沙盒定律 + 正典兼容），首席架构师备案。
- **权限**：提交提案、创作、评议投票加权、享分润权（创作池 + 运维池）。

### 2.3 架构评审团（共创者晋升，共识门槛）
- **进入条件**（须同时满足）：
  1. 在共创者身份上持续活跃（如 ≥3 个月 + 稳定贡献记录）；
  2. 累计维度积分达到较高门槛（C1–C4 综合，具体数值待定）；
  3. 展示正典理解与仲裁能力（参与过 ≥N 次评审/争议讨论）；
  4. 经**社区推选/共识**产生（草案：社区推选/共识产生），非自荐。
- **规模**：建议 5–9 人（奇数，避免平票），随社区规模可扩容。
- **审批**：社区公开提名 → 共创者投票 → 首席架构师确认。
- **权限**：审查提案、仲裁争议、共管生态回流基金（与社区代表）、参与治理修订。

### 2.4 首席架构师（发起人，固定）
- **进入**：项目发起人固定担任（Echo-Architect-0）。不设常规晋升通道。
- **权限边界**（对齐权限受限原理）：终审入正典、重大争议最终裁定，但**不能绕过评审团/社区共识单方面修订规则**（草案第九章：重大规则修订须社区共识 + 架构师确认）。
- **传承机制**（预留）：发起人可指定继承人（须经评审团 + 社区共识确认），或转为"评审团集体决策 + 首席架构师席位轮值"。此为长期演进项，非本期。

## 3. 各角色的退出机制

> 设计要点：退出分**主动退出**（个人选择）与**被动退出**（规则触发）。被动退出保障社区健康，防止"上得去下不来"。

### 3.1 观察者
- **主动退出**：随时可退出（注销账户，积分保留记录但不再累计）。
- **被动退出**：无（观察者无义务，不设除名；长期不活跃自动降为"休眠观察者"，不占名额）。

### 3.2 共创者
- **主动退出**：随时可申请退出；已获积分与分润权保留（已确认收益不受影响）。
- **被动降级**（观察者）：连续 N 个周期无贡献（提案/创作/评议）→ 降回观察者，保留历史积分。
- **被动除名**（违规）：刷量、抄袭、恶意破坏正典 → 经评审团仲裁（草案 6.4）→ 除名；严重者取消已获分润资格（按 5.3/6.4 处理）。
- **申诉**：被降级/除名者有权向仲裁小组申诉一次（评审团 + 社区代表复核）。

### 3.3 架构评审团
- **主动退出**：随时可请辞（席位空缺由候补/新选举填补）。
- **被动退出**：
  - **任期制**：建议任期（如 1 年），到期重选（连任可，但须再经社区推选）；
  - **不活跃**：连续 N 周期缺席评审 → 自动离任；
  - **失职/违规**：偏袒、泄露匿名信息、滥用仲裁权 → 社区动议罢免（须共创者投票 ≥ 阈值）+ 首席架构师确认。
- **轮换原则**：评审团定期轮换部分席位，防止权力固化（与"匿名性保护"共同防中心化胁迫）。

### 3.4 首席架构师
- **主动退出**：发起人可宣布让渡（触发传承机制，见 2.4）。
- **被动退出**：无常规罢免通道（发起人固定），但**权力边界受评审团 + 社区共识约束**（草案第九章）：若发起人试图绕过共识单方改规则，评审团可发起"共识否决"（社区投票否决其动议），使其决策无效。
- **传承**：继承人经评审团 + 社区共识确认后接任。

## 4. 三阶段演进

> 社区治理随规模分阶段放权。每阶段的进入/退出机制可微调，但核心角色边界（四角色 + 退出通道）不变。

### 阶段 1 · 冷启动（现在 → 公开前）
- **规模**：发起人 + 核心小组（首批共创者，种子 10–30 人）。
- **治理模式**：**小圈子集中决策**——发起人主导 + 评审团雏形（发起人邀请 2–3 名信任共创者组成临时评审组）；速度快，适合打磨正典与机制。
- **角色开放**：观察者开放注册（低门槛）；共创者按 2.2 正常晋升；评审团为"临时评审组"（不正式选举）；首席架构师 = 发起人。
- **进入/退出**：按第 2/3 节执行，但评审团选举暂缓（用邀请制）。
- **工具**：免备案工具栈（creator-sys 7.5：腾讯问卷/语雀/腾讯文档/微信群）。

### 阶段 2 · 公开扩张（仓库公开 / 招募启动后）
- **规模**：社区增长到数百人级。
- **治理模式**：**评审团正式化**——按 2.3 社区推选正式架构评审团（5–9 人）；重大规则修订走"社区共识 + 评审团 + 架构师"三确认（草案第九章）。
- **角色开放**：共创者门槛维持；评审团正式选举启动；生态岗体系运转（运维积分 + 运维池）。
- **工具**：Hub 站正式化（路线2 统一门面站，GitHub Pages 起步，备案仅作可选加速层）；积分看板公开公示（creator-sys 4.2）。

### 阶段 3 · 成熟治理（规模化 / 商业化启动后）
- **规模**：千人级 + 商业化。
- **治理模式**：**去中心化演进**——积分与投票上链（可审计）；模态子池/组织池/渠道池启用（多池可扩展条款）；争议仲裁由链上治理 + 评审团复核；首席架构师传承机制启用（若需要）。
- **角色开放**：组织（工作室/公会）以"组织池"参与；渠道（媒介）以"渠道池"参与。
- **工具**：上链账本（D1 预留上链可能）；合规化（法律/税务随商业化落地）。
